# Copywriting

Produce the requested copy in the user's format and voice. Use supplied briefs,
existing product text, `README.md`, and relevant interface context when present;
none is a prerequisite.

## Establish only missing context

Infer what is safe from the request and repository. Ask only for missing facts
that materially change the result, usually the audience, desired action,
channel, voice, or substantiation for a claim. Never invent metrics,
testimonials, customer quotes, pricing, guarantees, or legal claims. Do not
create or edit product documentation unless the user asks.

## Write

- Prefer concrete user outcomes to feature inventories.
- Use the audience's language, active voice, short sentences, and one main idea
  per section.
- Make the hierarchy and primary action obvious.
- Preserve meaningful brand voice; humor, questions, analogies, and punctuation
  are tools, not universal requirements or bans.
- Replace unsupported superlatives and vague buzzwords with demonstrable facts.
- For interfaces, keep labels predictable and error messages actionable without
  blaming the user.

Use `references/copy-frameworks.md` or
`references/natural-transitions.md` only when the task benefits from them.

## Deliver

Return only the artifact requested. Organize full-page copy by its actual
sections. Add rationale, variants, or annotations only when requested or when a
material choice needs explanation. Check consistency, claims, reading flow,
CTA/action agreement, and constraints before responding.
